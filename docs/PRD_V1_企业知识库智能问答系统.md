# 企业知识库智能问答系统（RAG）PRD（V1）

## 1. 产品定位
本产品面向中小科技型企业，解决企业知识碎片化、分散化与复用效率低的问题。  
系统基于 RAG 架构，将多源文档统一解析、结构化与索引，并通过混合检索与大模型生成能力，提供可追溯、可验证的智能问答服务。

## 2. 核心功能列表
1. 多格式文档解析与结构化处理
- 支持 PDF、Word、Excel、Markdown、TXT 的接入与解析。
- 提取文档结构信息：标题层级、段落、表格、页码/章节路径。
- 输出统一结构化数据供后续分块与索引使用。

2. 长文档语义分块
- 结合标题层级、段落边界和 token 长度进行语义优先切分。
- 保持上下文连续性，减少跨段语义断裂。
- 支持策略参数化与版本化管理。

3. 文本向量化与存储
- 提供轻量化 embedding 模型选型与替换能力。
- 建立向量写入、更新、重建与版本管理机制。
- 使用 Supabase/pgvector 作为优先向量存储方案。

4. 混合检索（语义+关键词）
- 融合向量检索和关键词检索（BM25/倒排）。
- 支持分数归一化、加权融合、可插拔重排。
- 提升召回的精准度与覆盖度。

5. 基于上下文的答案生成与溯源
- 基于检索上下文生成答案，返回引用来源。
- 支持不确定场景的拒答与置信度输出。
- 确保答案可追溯、可审计。

6. 管理与可观测能力
- 知识库管理、文档管理、任务状态管理。
- 检索日志、问答日志、基础评测看板。
- 为持续优化提供数据支持。

## 3. 用户流程
1. 管理员创建知识库并上传文档。
2. 系统执行解析、结构化、分块、向量化与索引构建。
3. 业务用户输入问题并选择知识库范围。
4. 系统执行混合检索并返回候选上下文。
5. LLM 基于上下文生成答案，附带引用来源。
6. 用户查看答案与引用，提交有用/无用反馈。
7. 管理员基于日志和评测结果优化策略。

## 4. 技术要求
1. 前端：Next.js + Tailwind CSS v4 + shadcn/ui。
2. 后端：FastAPI，提供文档处理、检索、问答、评测 API。
3. 存储：Supabase（结构化数据、元数据、日志），向量能力优先 pgvector。
4. 检索：向量检索 + 关键词检索 + 可插拔重排。
5. 模型：轻量 embedding 可替换；LLM 调用层抽象化。
6. 工程：模块化目录、统一配置中心、环境隔离、统一日志规范。
7. 安全：基础鉴权、文档访问控制、日志脱敏。

## 5. 验收标准
1. 文档处理成功率 >= 95%（支持格式范围内）。
2. 索引构建成功率 >= 99%，失败任务支持重试。
3. 混合检索 Top-5 命中率较纯关键词检索提升 >= 20%。
4. 问答可追溯率 = 100%（每条答案至少 1 条有效引用）。
5. P95 响应时延（检索+生成）<= 8s（中等规模知识库）。
6. 无依据回答率 <= 5%（抽样评测集）。
7. 关键接口可用性 >= 99%（验收周期内）。

## 6. 接口与类型关键约定
1. 文档元数据字段：`doc_id`, `kb_id`, `source`, `format`, `version`, `status`。
2. 分块字段：`chunk_id`, `doc_id`, `content`, `token_count`, `section_path`。
3. 检索结果字段：`chunk_id`, `score_vector`, `score_keyword`, `score_final`, `citation`。
4. 问答字段：`answer`, `citations[]`, `confidence`, `refuse_reason`。

## 7. 测试与验收场景
1. 多格式导入与解析一致性。
2. 长文档语义分块完整性。
3. 纯语义、纯关键词、混合检索效果对比。
4. 有依据回答与无依据拒答。
5. 并发问答与时延稳定性。
6. 引用可追溯与权限控制有效性。
