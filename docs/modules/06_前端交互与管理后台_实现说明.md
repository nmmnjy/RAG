# 06 前端交互与管理后台 - 实现说明（第一版）

## 1. 本次已实现内容

### 1.1 前端工程基础骨架
- 新增 `frontend/` 工程目录，完成 Next.js + Tailwind CSS v4 + TypeScript 基础配置。
- 建立 `src/app`（路由）、`src/components`（组件）、`src/features`（业务模块）、`src/types`（契约类型）分层。

### 1.2 页面信息架构
- 用户侧：
  - `/qa` 问答主流程
  - `/history` 问答历史
  - `/citations/[citationId]` 引用详情
- 管理侧：
  - `/admin/kbs` 知识库管理
  - `/admin/documents` 文档管理
  - `/admin/tasks` 任务状态
  - `/admin/logs` 日志看板

### 1.3 状态流转骨架
- 定义五段流程状态：`upload_state`、`parse_state`、`index_state`、`retrieve_state`、`answer_state`。
- 覆盖失败态与空态：
  - 检索空态：`retrieve_state = empty`
  - 拒答态：`answer_state = refused`
  - 任意阶段失败：`* = failed`

### 1.4 接口与数据结构定义
- 严格使用 PRD 字段命名（snake_case）：
  - 文档：`doc_id`, `kb_id`, `source`, `format`, `version`, `status`
  - 分块：`chunk_id`, `doc_id`, `content`, `token_count`, `section_path`
  - 检索：`chunk_id`, `score_vector`, `score_keyword`, `score_final`, `citation`
  - 问答：`answer`, `citations[]`, `confidence`, `refuse_reason`
- 统一 API 包装结构（按 00 冻结规范）：
  - 成功响应：`{ code, message, data, request_id, trace_id, ts }`
  - 错误响应：`{ code, message, details?, request_id, trace_id }`

## 2. 组件分层方案

### 2.1 分层
- `components/ui`: 通用基础组件（Button/Card/Badge）
- `components/layout`: 页面区块结构组件（SectionBlock）
- `features/qa`: 用户问答相关视图模型和 mock 数据
- `features/admin`: 管理后台相关 mock 数据
- `features/workflow`: 流程状态机与节点映射

### 2.2 当前可先做
- 页面框架、布局、导航、表格占位、状态标签样式
- 表单交互壳层（输入框、按钮、反馈入口）
- 流程状态节点展示与失败/空态 UI

### 2.3 依赖后端联调后做
- 实际上传、解析、索引、问答 API 调用
- 历史分页与筛选条件
- 引用原文定位与权限校验提示
- 任务状态实时更新（轮询或订阅）
- 日志查询过滤与导出

## 3. 联调约束（给后续 UI/联调线程）
- 所有请求/响应字段保持 snake_case，不做字段别名兼容。
- 若后端返回错误，使用 `code` + `message` 直出并携带 `request_id`。
- 页面状态以 `WorkflowState` 为单一来源，避免多处重复维护阶段状态。
