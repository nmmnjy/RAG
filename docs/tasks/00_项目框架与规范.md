# 00 项目框架与规范

## 模块目标
搭建统一工程骨架与协作规范，保障多线程并行开发时的接口一致性与可维护性。

## 范围边界
- 包含：目录结构、配置分层、环境变量规范、接口约定、日志与错误码规范。
- 不含：具体业务功能实现。

## 关键任务清单
1. 工程目录与职责划分
- 设计前端、后端、共享文档、评测与运维目录。
- 约定模块命名、文件命名和分层规则。

2. 配置与环境管理
- 设计 `dev/test/prod` 配置分层策略。
- 约定敏感配置管理规范与 `.env.example` 字段清单。

3. API 规范与契约
- 定义统一 API 命名风格、状态码、错误对象结构。
- 定义接口版本策略和兼容原则。

4. 日志与可观测规范
- 统一请求日志、任务日志、异常日志字段。
- 规定 trace_id/request_id 透传规则。

5. 开发协作规范
- 分支策略、提交规范、PR 检查项、代码评审清单。

## 交付物
- 工程骨架说明文档。
- 模块边界图。
- API 与错误码规范文档。
- 开发协作与提交流程文档。

## 验收标准
1. 新线程可根据文档在 30 分钟内完成本地环境准备。
2. API 返回结构和错误结构具备统一模板。
3. 日志字段具备可追踪性（含 request_id/trace_id）。

## 依赖与风险
- 依赖：PRD 字段约定。
- 风险：规范不统一导致跨模块联调成本上升。
