# 05 答案生成与溯源

## 文档状态
- 状态：已进入设计 + 代码骨架实现
- 作用：消费 `04` 冻结的 `HybridRetrieveResult`，输出稳定问答结果：`answer/citations/confidence/refuse_reason`
- 依赖基线：
  - `docs/specs/00_项目框架与规范.md`
  - `docs/specs/04_混合检索与重排.md`

## 边界与约束
- 负责：
  - 答案生成输入/输出契约
  - 可替换 LLM provider 接口
  - 引用拼接与溯源结构
  - 有依据回答 / 无依据拒答规则
  - 默认可运行 mock 流程
- 不负责：
  - 改动 04 检索契约
  - 接入真实线上大模型
  - 前端渲染策略实现

## 输入契约（直接消费 04）
- Schema 位置：`backend/app/schemas/answer_generation.py`
- `AnswerGenerationRequest`
  - `kb_id`
  - `query_text`
  - `retrieval_result`（类型：`HybridRetrieveResult`）
  - `max_context_chunks`
  - `min_score_threshold`
  - `min_evidence_chunks`
  - `refusal_answer_text`

说明：
- `retrieval_result.hits[]` 直接使用 04 稳定字段，不新增第五套检索命中结构。

## 输出契约（稳定字段）
- Schema 位置：`backend/app/schemas/answer_generation.py`
- `AnswerGenerationResult`
  - `answer`
  - `citations`
  - `confidence`
  - `refuse_reason`
  - `debug`（内部调试，不影响前端主流程）

约束：
- 输出必须始终包含 `answer/citations/confidence/refuse_reason` 四个字段。
- `citations` 至少 1 条有效引用时才允许进入“有依据回答”分支。
- 拒答时：
  - `answer` 返回拒答文案
  - `citations` 为空数组
  - `confidence = 0.0`
  - `refuse_reason` 非空

## citation 契约（前端可直接消费）
- `AnswerCitation`
  - `citation_id`
  - `chunk_id`
  - `doc_id`
  - `kb_id`
  - `section_path`
  - `snippet`
  - `score_final`
  - `source`
  - `citation`（透传 04 的 citation 原始字段）

说明：
- 前端可以直接使用 `citation_id + snippet + source + section_path` 渲染引用列表。
- 通过 `chunk_id/doc_id/kb_id` 可回链到检索与文档域。

## LLM Provider 可替换接口
- 位置：`backend/app/services/llm_provider.py`
- 抽象接口：`LLMProvider`
  - `provider_name`
  - `model_name`
  - `generate(request: LLMGenerateRequest) -> LLMGenerateResult`
- provider 工厂：`build_llm_provider()`
  - 基于配置决定使用 `mock` 或 `openai_compatible`
- 默认实现：`MockLLMProvider`
  - 可离线运行
  - 输出可重复（便于测试）
- 真实接入位：`OpenAICompatibleLLMProvider`
  - 当前已实现 OpenAI-compatible 实际 HTTP 调用：`POST {LLM_BASE_URL}/chat/completions`
  - 使用 `Authorization: Bearer {LLM_API_KEY}` 与 `messages` 协议
  - 从 `choices[0].message.content` 解析 `answer_text`

## Provider 切换与配置
- 配置来源：`backend/app/core/config.py`
- 相关环境变量：
  - `LLM_PROVIDER`：`mock | openai_compatible`
  - `LLM_MODEL`
  - `LLM_API_KEY`
  - `LLM_BASE_URL`
  - `LLM_REQUEST_TIMEOUT_MS`
  - `LLM_PROVIDER_ENABLE_REAL`
  - `LLM_PROVIDER_FALLBACK_TO_MOCK`
- 默认策略：
  - 默认 `LLM_PROVIDER=mock`
  - 当选择 `openai_compatible` 且 `LLM_PROVIDER_ENABLE_REAL=false`：
    - 若 `LLM_PROVIDER_FALLBACK_TO_MOCK=true`，自动回退 `mock`
    - 否则抛出 provider 配置错误

## Provider 错误路径与 fallback
- 位置：`backend/app/services/answer_generation_service.py`
- 行为：
  1. 正常调用当前 provider
  2. 若抛出 `LLMProviderError` 且允许 fallback：
     - 自动回退 `MockLLMProvider`
     - 在 `debug` 中记录 `provider_fallback_to` 与 `provider_fallback_reason`
  3. 若不允许 fallback：
     - 返回拒答结果，`refuse_reason = QA_LLM_PROVIDER_ERROR`
- `OpenAICompatibleLLMProvider` 错误映射（`backend/app/services/llm_provider.py`）：
  - 超时：`socket.timeout/TimeoutError/URLError(timeout)` -> `LLMProviderError("LLM provider request timeout.")`
  - 鉴权：HTTP `401/403` -> `LLMProviderError("LLM provider authentication failed.")`
  - 限流：HTTP `429` -> `LLMProviderError("LLM provider rate limited.")`
  - 服务异常：HTTP `5xx` -> `LLMProviderError("LLM provider service unavailable.")`
  - 其他 HTTP/network/无效 JSON -> `LLMProviderError(...)`
- 约束：
  - 无论 provider 如何切换，`AnswerGenerationResult` 稳定字段不变：`answer/citations/confidence/refuse_reason`

## 生成链路收敛规则
- 有依据回答：
  - 通过拒答策略（证据数量/分数阈值）
  - 且至少存在 1 条有效 citation（`chunk_id/doc_id/kb_id/snippet` 非空）
- 无依据拒答：
  - `QA_CONTEXT_EMPTY`
  - `QA_EVIDENCE_INSUFFICIENT`
  - `QA_CITATION_MISSING`
  - `QA_LLM_PROVIDER_ERROR`

## 拒答规则骨架
- 位置：`backend/app/services/refusal_policy.py`
- 策略：`RefusalPolicy.evaluate(...)`
- 基础规则：
  1. `hits` 为空 -> `QA_CONTEXT_EMPTY`
  2. `score_final >= min_score_threshold` 的证据片段数小于 `min_evidence_chunks` -> `QA_EVIDENCE_INSUFFICIENT`
  3. 其余场景允许回答

## 默认可运行流程（V1）
- 位置：`backend/app/services/answer_generation_service.py`
- 流程：
  1. 从 `retrieval_result.hits` 按 `score_final` 降序选取 `max_context_chunks`
  2. 执行 `RefusalPolicy`
  3. 若拒答：直接构造稳定结果
  4. 若可答：构建上下文块，调用 `LLMProvider.generate`
  5. 使用 `CitationBuilder` 拼接 `citations`
  6. 计算并返回 `confidence` 与最终结果

## 后端主链路 API（第二轮联调）
- 路径：`POST /api/v1/qa/answers`
- Endpoint 位置：`backend/app/api/v1/endpoints/qa.py`
- 请求 schema：`backend/app/schemas/qa.py` -> `QAAnswerRequest`
  - `kb_id`
  - `query_text`
  - `doc_id(optional)`
  - `top_k`
  - `vector_top_k`
  - `keyword_top_k`
  - `enable_rerank`
  - `max_context_chunks`
  - `min_score_threshold`
  - `min_evidence_chunks`
- 服务编排：`backend/app/services/qa_pipeline_service.py`
  1. 从 `01` 解析成功任务中读取 `structured_document`
  2. 经 `02` 分块生成 chunk
  3. 经 `03` 写入向量索引（内存）
  4. 调用 `04` 混合检索生成 `HybridRetrieveResult`
  5. 调用 `05` 答案生成返回稳定字段
- 响应结构：严格复用 00 统一响应包裹
  - 顶层：`{ code, message, data, request_id, trace_id, ts }`
  - `data` 内稳定包含：`answer`, `citations`, `confidence`, `refuse_reason`
