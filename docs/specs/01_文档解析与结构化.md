# 01 文档解析与结构化

## 文档状态
- 状态：已进入设计 + 代码骨架实现
- 作用：供 `02` 模块直接消费结构化输出，并为后续 `03`、`04`、`05` 提供上游契约
- 依赖基线：`docs/specs/00_项目框架与规范.md`

## 当前固定边界
- 负责：多格式文档解析任务编排、解析适配器接口、结构化输出 schema、任务状态流转。
- 不负责：向量化、检索、问答逻辑。
- 字段命名冻结：文档元数据必须包含 `doc_id`, `kb_id`, `source`, `format`, `version`, `status`。

## 格式支持矩阵（V1 骨架）
| format | 支持级别 | 适配器 | 当前能力 | 备注 |
| --- | --- | --- | --- | --- |
| pdf | skeleton | `PdfParserAdapter` | 返回占位结构化 section/block | 后续接入真实 PDF 抽取引擎 |
| word | skeleton | `WordParserAdapter` | 复用骨架逻辑 | 后续细化标题/段落样式抽取 |
| excel | skeleton | `ExcelParserAdapter` | 返回占位 table block | 后续补充 sheet/cell 坐标 |
| markdown | skeleton | `MarkdownParserAdapter` | 复用骨架逻辑 | 后续补充标题层级解析 |
| txt | skeleton | `TxtParserAdapter` | 复用骨架逻辑 | 后续补充段落分割策略 |

## 解析适配器接口
- 接口位置：`backend/app/parsers/adapters/base.py`
- 接口定义：
  - `adapter_name: str`
  - `parse(parse_input: ParseInput) -> StructuredDocument`
- 注册中心：`backend/app/parsers/registry.py`
- 适配器选择：按 `format` 路由到对应 adapter，不支持格式返回 `DOC_UNSUPPORTED_FORMAT`

## 结构化输出 schema（供 02 模块消费）
- Schema 位置：`backend/app/schemas/document_parse.py`
- 顶层对象：`StructuredDocument`
  - 必含字段：`doc_id`, `kb_id`, `source`, `format`, `version`, `status`
  - 扩展字段：`sections[]`, `metadata{}`
- section 对象：`StructuredSection`
  - `section_id`, `title`, `heading_level`, `section_path[]`, `page_start`, `page_end`, `blocks[]`
- block 对象：`StructuredBlock`
  - `block_id`, `block_type(paragraph|table)`, `content`, `section_path[]`, `page_no`, `table_rows`

## 任务状态流转（V1）
- 状态集合：`pending`, `parsing`, `succeeded`, `failed`, `retryable`
- 状态机位置：`backend/app/services/parse_task_state_machine.py`
- 合法流转：
  - `pending -> parsing`
  - `parsing -> succeeded|failed|retryable`
  - `retryable -> parsing|failed`
  - `failed -> retryable`
- 非法流转：返回 `COMMON_CONFLICT`

## API 契约（V1 骨架）
- 前缀：`/api/v1`
- 路径：
  - `POST /api/v1/document-parse/tasks` 创建解析任务
  - `POST /api/v1/document-parse/tasks/{task_id}/run` 触发任务执行
  - `POST /api/v1/document-parse/tasks/{task_id}/retry` 重试失败任务
  - `GET /api/v1/document-parse/tasks/{task_id}` 查询任务
  - `GET /api/v1/document-parse/tasks` 列表查询（支持 `kb_id`, `status`）
  - `POST /api/v1/document-parse/ingest` 上传（base64）并执行最小闭环解析
  - `GET /api/v1/document-parse/errors` 查询 `DOC_* -> HTTP` 映射
- 响应结构：统一遵循 00 规范，包含 `code`, `message`, `data`, `request_id`, `trace_id`, `ts`

## 错误码与重试规则
- 错误码：
  - `DOC_NOT_FOUND`
  - `DOC_PARSE_FAILED`
  - `COMMON_INVALID_ARGUMENT`
  - `COMMON_CONFLICT`
  - `COMMON_INTERNAL_ERROR`
- 重试策略：
  - 最大重试次数读取 `DOC_PARSE_MAX_RETRY`（默认 `3`）
  - `retry_count < max` 时失败状态置为 `retryable`
  - 达到上限后状态置为 `failed`

## 日志字段对齐说明
- 任务日志由 `DocumentParseService` 输出，携带：
  - `timestamp`, `level`, `service`, `env`
  - `request_id`, `trace_id`
  - `task_id`, `task_type`, `stage`, `retry_count`, `result`
  - `kb_id`, `doc_id`

## 第二轮：真实文件输入接入层升级（兼容 placeholder）
- 目标：在不改变 `StructuredDocument` 契约的前提下，为真实文件解析接入预留稳定边界。
- 优先接入格式：`markdown`、`txt`（真实输入骨架）；`pdf/word/excel` 继续走 placeholder。

### 新增接入抽象
- `ParseInput`（`backend/app/parsers/adapters/base.py`）
  - 字段：`metadata`, `file_path`
  - 作用：将文档元数据与真实文件路径解耦传递给 adapter。
- `ParserRegistry.parse(parse_input)`（`backend/app/parsers/registry.py`）
  - 返回：`(StructuredDocument, parser_mode)`
  - `parser_mode` 取值：`real` 或 `placeholder`

### 可配置实现选择
- 配置项（`backend/app/core/config.py`）：
  - `DOC_PARSE_PROVIDER`：`placeholder | hybrid | real`
  - `DOC_PARSE_REAL_FORMATS`：逗号分隔格式集合，默认 `markdown,txt`
  - `DOC_PARSE_ENABLE_FALLBACK`：真实解析失败时是否自动回落 placeholder，默认 `true`
- 选择规则：
  - `placeholder`：全部格式走 placeholder
  - `hybrid`：`DOC_PARSE_REAL_FORMATS` 内格式优先 real，失败可 fallback
  - `real`：`DOC_PARSE_REAL_FORMATS` 内格式强制 real，若启用 fallback 则失败回落 placeholder

### 真实解析路径边界（当前实现）
- Markdown：
  - adapter：`MarkdownFileParserAdapter`
  - 输入：`file_path` 指向本地 `.md` 文件
  - 行为：基础标题识别（`#`）+ 段落 block 抽取
- TXT：
  - adapter：`TxtFileParserAdapter`
  - 输入：`file_path` 指向本地 `.txt` 文件
  - 行为：按空行分段，生成 paragraph block

### fallback 与错误路径
- 当 real adapter 因缺失 `file_path`、文件不存在或读取失败触发 `AppError` 时：
  - 若 `DOC_PARSE_ENABLE_FALLBACK=true`，自动回落 placeholder adapter
  - 若关闭 fallback，沿原错误路径返回 `DOC_PARSE_FAILED`
- 该机制保证本地 mock/test 仍可沿 placeholder 路径运行，不破坏 05/07 可答样本与评测链路。

## 第三轮：真实输入最小闭环（上传 -> 结构化输出）
- 闭环路径：
  - 调用 `POST /api/v1/document-parse/ingest`
  - 服务端将 `file_content_base64` 写入 `DOC_PARSE_UPLOAD_DIR`
  - 推断 `format`、创建任务并执行解析，返回 `ParseTask`（含 `structured_document`）
- 上传请求字段：
  - `doc_id`, `kb_id`, `filename`, `version`, `file_content_base64`
- 结构化输出契约不变：
  - `StructuredDocument` 必含 `doc_id`, `kb_id`, `source`, `format`, `version`, `status`
  - 兼容 02 已消费结构，不新增破坏性字段。

## DOC 错误码与 HTTP 映射（第三轮）
| 错误码 | HTTP | 说明 |
| --- | --- | --- |
| `DOC_NOT_FOUND` | 404 | 任务不存在 |
| `DOC_UNSUPPORTED_FORMAT` | 400 | 上传文件扩展名不支持 |
| `DOC_SOURCE_INVALID` | 400 | 源内容非法（如空 payload、非法 base64） |
| `DOC_SOURCE_NOT_FOUND` | 404 | real parser 文件路径不存在 |
| `DOC_RETRY_NOT_ALLOWED` | 409 | 当前状态不允许重试 |
| `DOC_PARSE_FAILED` | 500 | 未归类解析异常 |
