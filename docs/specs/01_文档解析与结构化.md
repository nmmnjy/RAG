# 01 文档解析与结构化

## 文档状态
- 状态：已进入设计 + 代码骨架实现
- 作用：供 `02` 模块直接消费结构化输出，并为后续 `03`、`04`、`05` 提供上游契约
- 依赖基线：`docs/specs/00_项目框架与规范.md`

## 当前固定边界
- 负责：多格式文档解析任务编排、解析适配器接口、结构化输出 schema、任务状态流转。
- 不负责：向量化、检索、问答逻辑。
- 字段命名冻结：文档元数据必须包含 `doc_id`, `kb_id`, `source`, `format`, `version`, `status`。

## 格式支持矩阵（V1 骨架）
| format | 支持级别 | 适配器 | 当前能力 | 备注 |
| --- | --- | --- | --- | --- |
| pdf | skeleton | `PdfParserAdapter` | 返回占位结构化 section/block | 后续接入真实 PDF 抽取引擎 |
| word | skeleton | `WordParserAdapter` | 复用骨架逻辑 | 后续细化标题/段落样式抽取 |
| excel | skeleton | `ExcelParserAdapter` | 返回占位 table block | 后续补充 sheet/cell 坐标 |
| markdown | skeleton | `MarkdownParserAdapter` | 复用骨架逻辑 | 后续补充标题层级解析 |
| txt | skeleton | `TxtParserAdapter` | 复用骨架逻辑 | 后续补充段落分割策略 |

## 解析适配器接口
- 接口位置：`backend/app/parsers/adapters/base.py`
- 接口定义：
  - `adapter_name: str`
  - `parse(metadata: DocumentMetadata) -> StructuredDocument`
- 注册中心：`backend/app/parsers/registry.py`
- 适配器选择：按 `format` 路由到对应 adapter，不支持格式返回 `COMMON_INVALID_ARGUMENT`

## 结构化输出 schema（供 02 模块消费）
- Schema 位置：`backend/app/schemas/document_parse.py`
- 顶层对象：`StructuredDocument`
  - 必含字段：`doc_id`, `kb_id`, `source`, `format`, `version`, `status`
  - 扩展字段：`sections[]`, `metadata{}`
- section 对象：`StructuredSection`
  - `section_id`, `title`, `heading_level`, `section_path[]`, `page_start`, `page_end`, `blocks[]`
- block 对象：`StructuredBlock`
  - `block_id`, `block_type(paragraph|table)`, `content`, `section_path[]`, `page_no`, `table_rows`

## 任务状态流转（V1）
- 状态集合：`pending`, `parsing`, `succeeded`, `failed`, `retryable`
- 状态机位置：`backend/app/services/parse_task_state_machine.py`
- 合法流转：
  - `pending -> parsing`
  - `parsing -> succeeded|failed|retryable`
  - `retryable -> parsing|failed`
  - `failed -> retryable`
- 非法流转：返回 `COMMON_CONFLICT`

## API 契约（V1 骨架）
- 前缀：`/api/v1`
- 路径：
  - `POST /api/v1/document-parse/tasks` 创建解析任务
  - `POST /api/v1/document-parse/tasks/{task_id}/run` 触发任务执行
  - `GET /api/v1/document-parse/tasks/{task_id}` 查询任务
  - `GET /api/v1/document-parse/tasks` 列表查询（支持 `kb_id`, `status`）
- 响应结构：统一遵循 00 规范，包含 `code`, `message`, `data`, `request_id`, `trace_id`, `ts`

## 错误码与重试规则
- 错误码：
  - `DOC_NOT_FOUND`
  - `DOC_PARSE_FAILED`
  - `COMMON_INVALID_ARGUMENT`
  - `COMMON_CONFLICT`
  - `COMMON_INTERNAL_ERROR`
- 重试策略：
  - 最大重试次数读取 `DOC_PARSE_MAX_RETRY`（默认 `3`）
  - `retry_count < max` 时失败状态置为 `retryable`
  - 达到上限后状态置为 `failed`

## 日志字段对齐说明
- 任务日志由 `DocumentParseService` 输出，携带：
  - `timestamp`, `level`, `service`, `env`
  - `request_id`, `trace_id`
  - `task_id`, `task_type`, `stage`, `retry_count`, `result`
  - `kb_id`, `doc_id`
