# 02 语义分块策略

## 文档状态
- 状态：已进入设计 + 代码骨架实现（第三轮：契约收敛与回归固化）
- 作用：消费 `01` 产出的 `StructuredDocument`，输出供 `03` 直接消费的稳定 chunk 契约
- 依赖基线：`docs/specs/00_项目框架与规范.md`、`docs/specs/01_文档解析与结构化.md`

## 当前固定边界
- 负责：语义分块参数定义、策略版本化、特殊结构处理规则、chunk 输出 schema。
- 不负责：向量化、检索、问答逻辑。
- 字段命名冻结：chunk 对外最小必含 `chunk_id`, `doc_id`, `content`, `token_count`, `section_path`。

## 输入契约（来自 01）
- 输入对象：`StructuredDocument`
- 输入来源字段：`doc_id`, `kb_id`, `source`, `format`, `version`, `sections[]`
- 当前可稳定消费的 block 结构：
  - `block_type`: `paragraph|table`
  - `content`
  - `table_rows`
  - `section_path`

## 输出契约（供 03 消费）
- Schema 位置：`backend/app/schemas/chunking.py`
- 顶层对象：`ChunkBuildResult`
  - `doc_id`, `kb_id`, `source`, `format`, `version`
  - `strategy_name`, `strategy_version`
  - `params`, `chunk_count`, `chunks[]`
- chunk 对象：`ChunkRecord`
  - 冻结字段：`chunk_id`, `doc_id`, `content`, `token_count`, `section_path`
  - 扩展字段：`kb_id`, `chunk_index`, `strategy_name`, `strategy_version`, `source_block_ids`, `special_structure`, `metadata`

## 参数对象与策略版本
- 参数对象：`ChunkBuildParams`
  - `strategy_name`：当前默认 `structured_window`
  - `strategy_version`：当前默认 `2026.03.02`
  - `max_tokens_per_chunk`：默认 `220`
  - `overlap_tokens`：默认 `30`
  - `min_chunk_tokens`：默认 `20`
  - `preserve_table_block`：默认 `true`
  - `preserve_list_block`：默认 `false`
  - `preserve_code_block`：默认 `true`
  - `split_on_section_path_change`：默认 `true`
  - `sentence_boundary_fallback_split`：默认 `true`
- 参数校验规则：
  - `overlap_tokens < max_tokens_per_chunk`
  - `min_chunk_tokens <= max_tokens_per_chunk`
- 版本化规则（V1）：
  - `strategy_name + strategy_version` 唯一标识一套分块行为
  - 后续策略变更优先升级 `strategy_version`，并保留旧版本回放能力
- 落盘要求（第三轮固化）：
  - 每个 `ChunkBuildResult` 必须回传完整 `params` 与 `strategy_version`
  - 默认策略输出基线快照落盘于：
    - `backend/tests/fixtures/02_semantic_chunking/chunk_result_snapshot_sample_v2026_03_02.json`

## 默认策略（可运行实现）
- 策略实现：`StructuredWindowChunkingStrategy`（`backend/app/services/chunking_service.py`）
- 核心流程：
  1. 按 `sections -> blocks` 顺序扫描
  2. 识别特殊结构（表格/列表/代码块）
  3. 根据 `section_path` 变化执行边界切分，避免跨标题层级串块
  4. 对 fenced code（```）执行跨 block 聚合，按单代码块输出
  5. 超长段落优先按句子单元切分，必要时回退 token 滑窗切分
  6. 组装稳定 `ChunkRecord` 输出

## 特殊结构处理规则（V1 骨架）
- 规则位置：`backend/app/services/chunking_rules.py`
- 已覆盖：
  - 表格：`block_type=table` 时可独立成 chunk（默认开启）
  - 列表：通过前缀模式识别（`-/*/+/1.`），可配置是否独立成 chunk
  - 代码块：通过 fenced code（```）识别，支持“逐行 block 输入”场景的跨 block 聚合，可配置是否独立成 chunk
- 注意：
  - `01` 当前未显式提供 `list/code` 的 `block_type`，V1 通过 `content` 模式兜底识别

## 真实 markdown/txt 输入适配（第二轮）
- 真实输入来源：`01` 的 `MarkdownFileParserAdapter` 与 `TxtFileParserAdapter`
- 当前处理现状（增强前）：
  - markdown 逐行 block 导致 fenced code 可能被拆散，代码语义边界不稳定
  - txt 长段落按固定 token 窗口切分，可读性与语义连续性一般
  - section 内若存在路径变化，存在潜在跨路径合并风险
- 第二轮增强点：
  - 标题层级边界：开启 `split_on_section_path_change`，按 `section_path` 变更强制 flush
  - 代码块边界：新增 fenced code 聚合逻辑，支持“``` 起始行 + 中间行 + ``` 结束行”组合输出
  - 长段落切分：新增句子单元优先切分，再回退固定 token 窗口

## 错误码与异常
- 可能返回：
  - `COMMON_INVALID_ARGUMENT`（参数不合法）
  - `CHUNK_BUILD_FAILED`（策略执行失败）

## 供 03 消费的唯一输入说明（最终版）
- 唯一输入对象：`ChunkBuildResult`（`backend/app/schemas/chunking.py`）
- `chunks[]` 中冻结字段（必须存在且可直接消费）：
  - `chunk_id`：字符串，文档内唯一
  - `doc_id`：字符串，必须等于顶层 `doc_id`
  - `content`：非空字符串
  - `token_count`：正整数（当前为近似 token 估算）
  - `section_path`：字符串数组，可为空数组但字段必须存在
- 约束：
  - 输出顺序稳定（按扫描顺序和 `chunk_index` 递增）
  - 同一策略与同一参数输入下，输出可复现（由快照回归保障）
  - `strategy_name + strategy_version + params` 作为结果可追溯标识
- 异常行为：
  - 参数非法（如 `overlap_tokens >= max_tokens_per_chunk`）返回 `COMMON_INVALID_ARGUMENT`
  - 策略执行异常返回 `CHUNK_BUILD_FAILED`
  - 遇到空 section 或空 block 内容时跳过，不产出空 `content` chunk
  - 未闭合 fenced code 时回退普通文本处理路径，不抛出结构错误
