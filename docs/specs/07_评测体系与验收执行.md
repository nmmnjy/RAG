## 统一评测输入契约
- Schema 位置：`backend/app/schemas/evaluation.py`
- 顶层输入：`OfflineEvaluationDatasetInput`
  - `dataset_id`
  - `dataset_version`
  - `description`
  - `cases[]`
- case 输入：`OfflineEvaluationCaseInput`
  - `case_id`, `case_name`, `query_text`
  - `structured_document`（直接使用 `01` 的 `StructuredDocument`）
  - `retrieve_config`（仅评测执行参数，不新增业务命中结构）
  - `answer_config`（仅评测执行参数）
  - `assertions`（规则型断言）
    - `min_answer_confidence`
    - `evidence_text`
    - `require_evidence_hit`

说明：
- 评测执行时会基于 `structured_document` 串联调用 02/03/04/05 骨架服务。
- `doc_id/kb_id/chunk_id/score_*` 等业务字段全部复用 00~05 冻结命名。

## 统一评测输出契约
- Schema 位置：`backend/app/schemas/evaluation.py`
- 检查项：`EvaluationCheckResult`
  - `check_name`
  - `dimension_name`
  - `passed`
  - `metric_value`
  - `assertion_result`
  - `failure_reason`
- 维度结果：`EvaluationDimensionResult`
- case 报告：`OfflineEvaluationCaseReport`
- 汇总报告：`OfflineEvaluationReport`

## 评测维度与基础检查（V1）
- 解析/结构化可用性：`parse_structured`
  - `parse_status_succeeded`
  - `parse_section_count_min`
  - `parse_blocks_non_empty`
- 分块契约与质量基础检查：`chunk_quality`
  - `chunk_count_min`
  - `chunk_contract_required_fields`
  - `chunk_section_path_presence`
- 检索结果结构与命中基础检查：`retrieval_quality`
  - `retrieval_hit_count_min`
  - `retrieval_contract_required_fields`
  - `retrieval_expected_top_hit`
- 答案生成结构与拒答行为检查：`answer_quality`
  - `answer_contract_required_fields`
  - `answer_non_empty_for_answerable`
  - `answer_refusal_behavior`
  - `answer_citations_non_empty_when_answered`
  - `answer_confidence_min_for_answerable`
  - `answer_evidence_hit_for_answerable`

## 可答样本纳入（第二轮）
- 标准样本来源：`backend/tests/fixtures/07_answerable_qa/qa_answerable_case_v1.json`
- 已纳入数据集：
  - `evaluation/datasets/sample_v1/manifest.json`
  - `evaluation/datasets/qa_demo_v1/manifest.json`
- 可答链路检查定义（进入离线报告，不仅是单测）：
  - `answer` 非空：`answer_non_empty_for_answerable`
  - `citations` 非空：`answer_citations_non_empty_when_answered`
  - `confidence` 达标：`answer_confidence_min_for_answerable`
  - `refuse_reason` 为空：`answer_refusal_behavior`（`expected_refuse_reason = null`）
  - 证据命中：`answer_evidence_hit_for_answerable`
    - 断言：`answer` 或 `citations[].snippet` 至少一处包含 `assertions.evidence_text`

## 验收报告结构（主线程可直接汇总）
- 报告字段：
  - `report_id`, `dataset_id`, `dataset_version`, `generated_at`
  - `summary`：`case_count`, `case_passed_count`, `answerable_case_count`, `answerable_case_passed_count`, `check_count`, `check_passed_count`, `check_failed_count`, `pass_rate`
  - `gate_results[]`
  - `release_blocked`
  - `case_reports[]`
- case 级重点展示：
  - `output_summary.answerable_chain_passed`
  - `answer_evidence_hit_for_answerable` 检查项的 `passed/metric_value/failure_reason`
- 输出格式：JSON（UTF-8）
- 产物目录：`evaluation/reports/`

## 发布门禁最小规则骨架
- 规则 schema：`ReleaseGateRule` / `ReleaseGateResult`
- 当前默认规则：
  - `gate_pass_rate_min_0_90`：总检查通过率 `>= 0.90`
  - `gate_parse_dimension_must_pass`：每个 case 的解析维度必须通过
  - `gate_retrieval_dimension_must_pass`：每个 case 的检索维度必须通过
  - `gate_answer_dimension_must_pass`：每个 case 的答案维度必须通过
  - `gate_answerable_evidence_hit_must_pass`：可答样本 `answer_evidence_hit_for_answerable` 必须通过
- 阻断逻辑：
  - 任一门禁失败 => `release_blocked = true`
