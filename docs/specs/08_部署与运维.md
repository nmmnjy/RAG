# 08 部署与运维

## 文档状态
- 状态：已补充（待主线程拍板目录归属）
- 作用：供前后端线程统一参考部署与环境约束

## 当前固定边界
- 本模块负责部署拓扑、环境规划、监控告警和回滚策略。
- 本模块不负责业务功能实现。
- 环境变量、日志和链路追踪必须对齐 `00` 规范。

## 与 `00` 规范目录蓝图（`infra/`）映射关系
- `ops/vercel/*` -> `infra/vercel/*`
- `ops/backend/*` -> `infra/supabase/*`（说明：当前含 FastAPI 容器与 Supabase 接入说明，主线程可按实际再细分）
- `ops/environments/*` -> `infra/scripts/` 下的环境模板子目录，或 `infra/env/`（需主线程定稿）
- `ops/scripts/*` -> `infra/scripts/*`
- `ops/topology/*`、`ops/monitoring/*`、`ops/runbooks/*` -> `infra/` 下对应子目录（需主线程定稿）

## 目录归属决策材料
### 方案 A：主线程决定保留 `ops/`
- 需要修改的共享文档：
- `docs/specs/00_项目框架与规范.md`：将目录蓝图中的 `infra/` 改为 `ops/`，并同步目录职责描述。
- `docs/README_任务分发总览.md`：如有目录引用，改为 `ops/`。
- 各模块 `docs/tasks/*.md`、`docs/specs/*.md`、`docs/changes/*.md` 中出现 `infra/` 的地方需统一替换或补充兼容说明。
- 影响：目录命名统一成本低（无需迁移文件），但需要修改共享基线并同步所有线程认知。

### 方案 B：主线程决定统一迁移到 `infra/`
- 迁移范围（仅列范围，不在本次执行）：
- `ops/vercel/*`
- `ops/backend/*`
- `ops/environments/*`
- `ops/monitoring/*`
- `ops/runbooks/*`
- `ops/scripts/*`
- `ops/topology/*`
- `ops/README.md`
- 影响：保持与 `00` 基线一致，减少后续歧义；但需一次性迁移路径并更新引用文档（含 `docs/modules/08_部署与运维_实施说明.md`、`docs/changes/08_实施记录.md`）。

## 本模块建议
- 在主线程拍板前，冻结目录新增策略：仅在现有 `ops/` 内补充，不扩散第三套目录。
- 拍板后由主线程统一发起路径收敛，避免多线程重复迁移导致冲突。
