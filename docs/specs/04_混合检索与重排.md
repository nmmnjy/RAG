# 04 混合检索与重排

## 文档状态
- 状态：设计 + 代码骨架实现（第二轮：效果增强准备）
- 作用：消费 `03` 冻结语义命中契约（`VectorQueryHit`），融合关键词召回，输出 `05` 可直接消费的稳定检索结果

## 边界约束
- 负责：
  - 双路召回（语义 + 关键词）流程骨架
  - 分数归一化与融合策略
  - 参数配置化（便于后续调优）
  - 可插拔重排接口边界
- 不负责：
  - 修改 `03` 向量查询命中结构
  - 修改 `05` 已消费的混合检索结果字段
  - 当前阶段线上最优效果

## 冻结输入（来自 03）
- 必须直接消费 `VectorQueryHit`：
  - `chunk_id`, `doc_id`, `kb_id`, `content`, `section_path`, `score_vector`, `citation`, `metadata`
- 禁止在 04 再定义第四套语义检索命中结构。

## 输出契约（供 05 直接消费）
- `HybridRetrieveResult.hits[]` 最小稳定字段：
  - `chunk_id`
  - `score_vector`
  - `score_keyword`
  - `score_final`
  - `citation`
  - `content`
- 同时包含：`doc_id`, `kb_id`, `section_path`, `metadata`

## 参数配置位（第二轮新增整理）
- Schema：`backend/app/schemas/retrieval.py`
- `HybridRetrieveTuningConfig`
  - `top_k`
  - `vector_top_k`
  - `keyword_top_k`
  - `enable_rerank`
  - `fusion_config`
- 兼容策略：
  - `HybridRetrieveRequest` 仍保留原有顶层字段（`top_k/vector_top_k/keyword_top_k/enable_rerank/fusion_config`）
  - 新增 `tuning_config`，用于集中配置
  - 执行时通过 `get_effective_tuning_config()` 统一解析，默认行为不变

## 融合策略（可配置骨架）
- Schema：`HybridFusionConfig`
  - `strategy_name`（当前支持：`weighted_sum`）
  - `normalization_method`（当前支持：`min_max`）
  - `vector_weight`
  - `keyword_weight`
- 实现：`backend/app/services/hybrid_fusion.py`
  - 抽象：`FusionStrategy`
  - 默认策略：`WeightedSumFusionStrategy`
  - 注册表：`FUSION_STRATEGY_REGISTRY`
  - 解析函数：`resolve_fusion_strategy()`
- 默认公式：
  - `score_final = vector_weight * norm(score_vector) + keyword_weight * norm(score_keyword)`

## 重排接口边界（当前仍可运行）
- 实现：`backend/app/services/reranker.py`
- 抽象接口：`Reranker`
  - `reranker_name`
  - `rerank(request: RerankRequest) -> list[HybridRetrieveHit]`
- 边界约束：
  - 重排器仅处理候选顺序或 `score_final` 调整
  - 不应改写 `chunk_id`、`score_vector`、`score_keyword` 的语义
- 默认实现：`NoopReranker`（占位，可替换）

## 默认可运行流程
- 实现：`backend/app/services/hybrid_retrieval_service.py`
1. query 文本向量化
2. 语义召回（03）
3. 关键词召回（04）
4. 按可配置融合策略计算 `score_final`
5. 可选重排
6. 输出稳定 `HybridRetrieveResult`

## 测试最小覆盖
- `backend/tests/unit/test_hybrid_retrieval_service.py`
  - 关键词检索可返回 `score_keyword`
  - `min_max + weighted_sum` 正常工作
  - 改变融合权重可影响排序
  - `tuning_config.top_k` 可影响返回候选数
  - 输出字段保持 05 可消费结构

## 风险与待确认项
- 当前关键词检索仍为内存实现，未覆盖持久化倒排索引性能。
- 当前默认重排器为 `Noop`，未覆盖模型重排质量评估。
- 待确认：
  - 是否在 04 阶段指定线上关键词检索基线（如 BM25/ES/PG trigram）
  - 是否要求默认启用轻量 reranker（当前为占位）
