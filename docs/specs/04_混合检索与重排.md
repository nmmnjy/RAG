# 04 混合检索与重排

## 文档状态
- 状态：第三轮收敛
- 目标：在不修改 03/05 既有契约前提下，冻结 04 输入/输出契约，稳定融合与重排行为，并具备可复现实验能力

## 冻结边界
- 依赖输入（来自 03，禁止改动）：
  - `VectorQueryHit`：`chunk_id`, `doc_id`, `kb_id`, `content`, `section_path`, `score_vector`, `citation`, `metadata`
- 04 输出（供 05 消费，字段冻结）：
  - `chunk_id`
  - `score_vector`
  - `score_keyword`
  - `score_final`
  - `citation`
  - 以及必要内容字段：`content`, `doc_id`, `kb_id`, `section_path`, `metadata`

## 输入契约（04 内部）
- 关键词召回命中：`KeywordQueryHit`
  - `chunk_id`, `doc_id`, `kb_id`, `content`, `section_path`, `score_keyword`, `citation`, `metadata`
- 融合输入：
  - `vector_scores: dict[chunk_id, score_vector]`
  - `keyword_scores: dict[chunk_id, score_keyword]`

## 参数配置位（收敛版）
- 请求对象：`HybridRetrieveRequest`
- 调优集中配置：`HybridRetrieveTuningConfig`
  - `top_k`：最终返回条数，`[1,100]`
  - `vector_top_k`：语义召回候选数，`[0,100]`；`0` 表示关闭语义通道
  - `keyword_top_k`：关键词召回候选数，`[0,100]`；`0` 表示关闭关键词通道
  - `enable_rerank`：是否执行重排
  - `fusion_config`：融合策略参数
- 兼容性：
  - `HybridRetrieveRequest` 保留历史顶层字段（`top_k/vector_top_k/keyword_top_k/enable_rerank/fusion_config`）
  - 新增 `tuning_config`；执行时由 `get_effective_tuning_config()` 统一解析，默认行为不变

## 融合策略（代码与文档对齐）
- 归一化方法：`min_max`
  - 公式：`norm = (x - min) / (max - min)`
  - 边界：
    - 空输入 -> 空输出
    - `max == min` 且 `max <= 0` -> 全部 `0.0`
    - `max == min` 且 `max > 0` -> 全部 `1.0`
- 策略名：`weighted_sum`（当前默认）
  - 公式：`score_final = vector_weight * norm(score_vector) + keyword_weight * norm(score_keyword)`
- 扩展骨架：
  - 抽象接口：`FusionStrategy`
  - 注册表：`FUSION_STRATEGY_REGISTRY`
  - 解析函数：`resolve_fusion_strategy()`

## top_k 行为可复现规则
- `vector_top_k = 0`：不发起语义召回
- `keyword_top_k = 0`：不发起关键词召回
- `top_k`：对融合后（及可选重排后）结果统一截断
- 排序稳定性：
  - 主键：`score_final` 降序
  - 次键：`chunk_id` 升序（同分稳定）

## 重排链路稳定化
- 接口：`Reranker`
  - `reranker_name`
  - `rerank(request) -> list[HybridRetrieveHit]`
- 默认行为：
  - `enable_rerank = false`：不重排，直接返回融合排序结果
  - 默认实现：`NoopReranker`
- 失败回退：
  - `enable_rerank = true` 但重排抛错时，回退到“未重排融合结果”
  - `debug` 字段记录：
    - `rerank_status`：`disabled | applied | fallback`
    - `rerank_error`：失败信息（fallback 时）
